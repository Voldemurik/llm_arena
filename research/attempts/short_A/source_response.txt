<section id="metrics-theory"><div class="wrap" id="metrics">
  <h2>Ключевые метрики</h2>
  <p class="lead">Нажмите на карточку, чтобы раскрыть определение, формулу и типичные ловушки.</p>
  <div class="acc">
    <details open><summary>🎯 Success rate (доля решённых задач)</summary><div class="body">
      Доля запусков, где результат прошёл проверку по критерию успеха.
      <span class="formula">success = решено / всего запусков</span>
      Всегда указывайте доверительный интервал: при 50 прогонах разброс ±10–14 п.п., при 500 — около ±4 п.п. Критерий успеха нужно определить заранее: точное совпадение, прохождение тестов, итоговое состояние базы данных, оценка судьи.
    </div></details>
    <details><summary>💰 Стоимость: за запуск и за успешное решение</summary><div class="body">
      Токены на вход и выход × цена модели + вызовы инструментов.
      <span class="formula">cost per success = суммарные затраты / число успехов</span>
      Средняя цена за запуск скрывает неудачи: дешёвый агент, который решает 30 % задач, может оказаться дороже в пересчёте на успех. В ReAct контекст растёт с каждым шагом, поэтому цена растёт быстрее числа шагов.
    </div></details>
    <details><summary>⏱ Задержка: p50, p95, p99</summary><div class="body">
      Время от запроса до результата. Среднее почти бесполезно: пользователи запоминают «хвост».
      <span class="formula">p95 = значение, которое не превышают 95 % запусков</span>
      Последовательные шаги суммируются, параллельные ветви (best-of-N, мультиагент) могут сокращать суммарное время, но увеличивают цену.
    </div></details>
    <details><summary>👣 Количество шагов и вызовов инструментов</summary><div class="body">
      Показатель эффективности траектории. Много шагов — это больше цена, задержка и шанс ошибки. Следите за «лишними» шагами (повторы, зацикливание) и долей запусков, упёршихся в лимит.
    </div></details>
    <details><summary>🧭 Качество траектории и инструментов</summary><div class="body">
      Правильность выбора инструмента, корректность аргументов, отсутствие лишних вызовов, соблюдение политик. Агент мог получить верный ответ «случайно» — траектория это показывает.
    </div></details>
    <details><summary>🔁 Надёжность: pass@k и pass^k</summary><div class="body">
      <code>pass@k</code> — хотя бы один успех из k попыток; <code>pass^k</code> — все k попыток успешны. Для продакшена важен второй показатель. См. интерактивный раздел ниже.
    </div></details>
    <details><summary>🛡 Безопасность и побочные эффекты</summary><div class="body">
      Нарушения политик, лишние необратимые действия (удаление, платежи), утечки данных. Метрика «успех» без неё опасна: агент может «решить» задачу вредным способом.
    </div></details>

function runEpisode(rng,s,cfg,wantTrace){
  const m=MODELS[cfg.model],T=TASKS[cfg.task],c=cfg.complexity;
  const N=Math.max(1,Math.round(.6*c+T.base*.5));
  const on=Object.keys(cfg.tools).filter(k=>cfg.tools[k]);

    let p=m.skill*s.quality+bonus-.025*(c-1)*s.cx;

function simulate(s,cfg,runs,seed){
  const rng=mulberry32(seed);
  const S={s,n:runs,ok:0,cost:0,steps:[],lat:[],calls:0,tok:0,fails:{timeout:0,loop:0,exhausted:0,undetected:0},costs:[]};
  for(let i=0;i<runs;i++){
    const E=runEpisode(rng,s,cfg,false);
    if(E.success)S.ok++;else S.fails[E.reason]++;
    S.cost+=E.cost;S.steps.push(E.steps);S.lat.push(E.lat);S.calls+=E.calls;S.tok+=E.tin+E.tout;
  }
  S.success=S.ok/runs;S.ci=wilson(S.ok,runs);
  S.costMean=S.cost/runs;S.cps=S.ok?S.cost/S.ok:Infinity;
  S.latSorted=[...S.lat].sort((a,b)=>a-b);S.stepsSorted=[...S.steps].sort((a,b)=>a-b);
  S.p50=pctl(S.latSorted,.5);S.p95=pctl(S.latSorted,.95);
  S.stepsMean=S.steps.reduce((a,b)=>a+b,0)/runs;S.stepsP95=pctl(S.stepsSorted,.95);
  S.callsMean=S.calls/runs;S.tokMean=S.tok/runs;
  return S;
}

function renderInsights(){

}

**Что внутри**

- **Лаборатория.**
  - Шесть стратегий: один запрос, ReAct, Plan-and-Execute, ReAct с рефлексией, мультиагент и Best-of-3 с верификатором.
  - Настройки: тип и сложность задачи, размер модели, лимит шагов, инструменты, число прогонов и seed.
  - При каждом изменении запускается Монте-Карло-симуляция по всем стратегиям.
- **Метрики.** Успешность с 95% доверительным интервалом, стоимость на задачу и за успешное решение, задержка p50 и p95, число шагов. Можно зафиксировать базу и смотреть, как меняются показатели относительно неё.
- **Вкладки результатов.**
  - Сравнение стратегий по шести показателям.
  - Парето-диаграмма «цена — успех» с размером пузыря по задержке.
  - Гистограммы шагов и задержки, разбивка причин неудач.
  - Пошаговая траектория одного запуска, включая «скрытые ошибки», которых агент не заметил.
- **Автоматические выводы.** Сайт подсказывает, какая стратегия дешевле за успех, где лимит шагов обрывает запуски и когда агент не нужен.
- **Теория.** Разделы про метрики, методы оценки, бенчмарки (SWE-bench, GAIA, WebArena, τ-bench), интерактивный pass@k и pass^k, тест из 6 вопросов.
- **Дополнительно.** Светлая и тёмная темы, адаптивная вёрстка, быстрые сценарии («Простой вопрос», «Жёсткий лимит шагов» и другие).

Цены, вероятности и задержки в модели выбраны для иллюстрации, а не измерены на реальных системах. Это указано в подвале сайта.
